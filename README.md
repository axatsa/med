# Иммуногенетический прогноз риска ПН → ПЭ

Веб-сервис для прогнозирования риска перехода **плацентарной недостаточности** в **преэклампсию** на основе иммунологических, ангиогенных и генетических маркеров.

---

## Что делает система

После ввода данных пациентки (клинических, лабораторных, генетических) система:

1. Рассчитывает **вероятность перехода ПН → ПЭ** (0–100%)
2. Определяет **уровень риска**: НИЗКИЙ / УМЕРЕННЫЙ / ВЫСОКИЙ
3. Показывает **основные предикторы** с вкладом каждого в % 
4. Выдаёт **рекомендации** врачу
5. Строит **график динамики маркеров** по неделям беременности
6. Генерирует **PDF-отчёт** на русском или узбекском языке
7. Сохраняет всё в **базу пациентов** (SQLite)

## Быстрый старт

### 1. Первая установка (один раз)

```bash
cd /путь/к/med
bash setup.sh
```

Скрипт сам:
- создаёт виртуальное окружение `venv/`
- устанавливает зависимости
- скачивает шрифты для PDF
- обучает XGBoost модель

### 2. Запуск сервера

```bash
venv/bin/python app.py
```

Сервер запустится на **http://localhost:8000**

> **Почему 8000, а не 5000?**  
> На macOS порт 5000 занят системным процессом AirPlay Receiver.

### 3. Открыть фронтенд

Открыть в браузере: **http://localhost:8000**  
Или напрямую файл: `frontend/index.html`

## Как работает модель

Используется **ансамбль двух методов**:

### Метод 1: Взвешенный клинический скоринг

Каждый маркер получает баллы на основе опубликованных пороговых значений:

| Маркер | Порог высокого риска | Баллы |
|--------|---------------------|-------|
| sFlt-1/PlGF ratio | > 38 | 22 |
| IL-6 | > 5 pg/ml | 7–12 |
| VEGF-A | < 100 pg/ml | 8–10 |
| MAP | > 90 мм рт.ст. | 6–10 |
| ПЭ в анамнезе | да | 10 |
| IL-10 | < 5 pg/ml | 6–8 |
| IL6 rs1800795 GG | — | 7 |
| IL10 rs1800896 AA | — | 5 |

### Метод 2: XGBoost

Обучен на 2000 синтетических случаях, сгенерированных по клиническим правилам из литературы. AUC на тестовой выборке: **0.89**.

> Когда будут реальные данные пациентов — запустить `python scripts/train_model.py` с ними, и качество модели существенно вырастет.

### Итоговый риск

```
Итог = 0.45 × взвешенный_скоринг + 0.55 × XGBoost
```

## FAQ

**Q: Почему синтетические данные, а не реальные?**  
A: Реальные данные пациентов не были предоставлены. Синтетические данные построены на основе клинических порогов из научных публикаций (PIERS, PRISM study). Как только будут реальные данные — запустить `scripts/train_model.py` с ними.

**Q: Точность модели надёжна?**  
A: AUC 0.89 на синтетических данных — это хорошо, но не гарантирует такое же качество на реальных пациентах. Система создана для **поддержки** клинических решений, а не для их замены.

**Q: Как подключить готовый фронтенд от Мухлисы?**  
A: CORS уже включён для всех источников (`*`). Достаточно в её коде указать base URL `http://localhost:8000/api`. Все ответы — JSON.

**Q: Как добавить аутентификацию позже?**  
A: Добавить `Flask-JWT-Extended`, создать `/api/login`, и добавить декоратор `@jwt_required()` на нужные маршруты в `routes/`.

**Q: Как изменить алгоритм расчёта?**  
A: Веса и пороги — в `models/risk_calculator.py`, функция `_calculate_weighted_score`. Всё задокументировано в коде.

**Q: Как переобучить модель на реальных данных?**  
A: Подготовить CSV с теми же колонками что в `scripts/train_model.py` → адаптировать загрузку данных → запустить `python scripts/train_model.py`. Модель сохранится в `assets/pe_model.pkl` и подхватится автоматически.

**Q: Где хранятся данные пациентов?**  
A: В файле `data/med.db` (SQLite). Для просмотра можно использовать [DB Browser for SQLite](https://sqlitebrowser.org/).

**Q: Как задеплоить на сервер?**  
A: Поставить `gunicorn` (`pip install gunicorn`) и запустить: `gunicorn "app:create_app()" -b 0.0.0.0:8000`. Для nginx — проксировать на 8000.
